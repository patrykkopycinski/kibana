4 Tiered Self-Evolution Strategy
Meta Agent Decision Model
1
Deterministic Workflow PREFER
For predictable tasks: ES aggregations, threshold alerts, data cleanup, notifications. Uses only elasticsearch.*, kibana.request, console steps. No LLM cost, 100% reliable.
2a
Create / Update Skill MODULAR KNOWLEDGE
Reusable knowledge modules bundling domain expertise (content) + tool access (tool_ids). Created via POST /api/agent_builder/skills. Auto-matched to agents by the platform. Use for playbooks, runbooks, environment baselines, technique-specific response plans.
2b
Enrich Existing Agent BEHAVIORAL PATCH
Appends an instruction_patch to a core agent's prompt via workflow_modify_step. Additive only — never removes or contradicts existing behavior. Use for agent-specific tweaks (thresholds, output format). Targets: triage, entity, hunt, deteng, watchdog.
3
New Agent LAST RESORT
Requires: (a) task needs LLM reasoning, (b) no existing agent covers domain, (c) no duplicate in registry, (d) ≥3 data points justify need. Must include justification[] array. Creates agent + scheduled workflow.
Rate limits: max 1 action/cycle. Oscillation guard (>10% swing 3×) → no_action. All decisions go to .soc-recommendations for human review.

6 AI Agent Mesh — 4 Agents + 7 Skills, connector-id: opus (Claude Opus 4.7)

Consolidated from 9 agents to 4 via mandatory self-validation, agent merging, and skill/workflow conversion. Extended with 4 new skills for proactive hunting, attack chain analysis, capability gap detection, and tiered response containment. Entity enrichment and threat hunting are now phases within the unified triage agent. Watchdog, difficulty evaluation, and architecture review are skills on the meta-agent. Case creation and response are deterministic workflows.
