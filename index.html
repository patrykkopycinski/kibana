1. What is tested, and why

security-team#19927 (gap G19): the Escalations feature promises that an escalation's summary and its context chat draw on every investigation linked to it. Before this suite nothing measured that, and a summary that silently ignores the newest investigation looks fluent while being wrong. Each case hides one fact only in the last investigation, so a missing mention is attributable.

Claim under testEvaluators
Claim 1: The escalation summary reflects every linked investigation.SummaryKeyMentionRecall, ClaimGrounding, UnsupportedNumericSpecifics
Claim 2: The escalation-context chat answers from all of the linked investigations.ChatKeyMentionRecall

Not measured here: summary prose quality or tone, latency or cost, the escalation UI, and non-English input. Key-mention recall proves a key was mentioned, not that it is attached to the right claim; only ClaimGrounding checks that, and it is an LLM judge.

2. How

16 cases. Each is an escalation with 2-5 linked investigations carrying distinct planted facts (unique keys: IPs, hashes, CVE ids, account names). Every case plants one fact that exists only in the last linked investigation (the canary for claim 1). Each chat question has an answer derivable from exactly one investigation. Dataset validation at the evidence head reported zero issues.

The investigation traces a supply-chain compromise through the CI/CD pipeline. It began when pull request #4471, merged by the automated account svc-ci-bot, modified `.github/workflows/deploy.yml` on runner ci-runner-9 to curl and run a script from http://203.0.113.9/init.sh. Shortly after, a rogue package, internal-string-utils version 99.99.99, appeared in the internal npm registry — published from an external namespace rather than the trusted publisher — with registry logs tracing the upload to API key ci-publish-key-31f2. The compromise then surfaced in build artifacts: build 8842 of edge-gateway-2.14.0.tgz was found to contain a postinstall hook that reaches out to resolve-dns.example at install time. The investigation concluded that the artifact signing key gpg-key-2026-C (id 4F2A91C7) had been exfiltrated from the runner keychain to 198.51.100.99, and that three artifacts were signed with this stolen key after the exfiltration — indicating the attacker used it to make malicious builds appear as trusted, legitimately signed releases.
