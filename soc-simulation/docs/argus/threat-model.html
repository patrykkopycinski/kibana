1 The Mythos-Era Threat
Why This Strategy Exists

Anthropic's Mythos — restricted under Project Glasswing — demonstrates that a single frontier model can discover zero-day vulnerabilities, generate working exploits, synthesize dozens of polymorphic variants in minutes, and operate autonomously across a kill chain. Every commercial defender must now assume adversaries have access to equivalent capabilities, whether from Mythos itself, its successors, or open-source approximations. The traditional SOC — built around human-tempo triage, signature rules, and CVE patch windows — is architecturally misaligned with this threat. ARGUS is our architectural response.

A Mythos-era adversary applies four pressures that existing SOC architectures were not designed to absorb. The shape of ARGUS is a direct answer to each.
Pressure #1

Exploit Time Compression

CVE disclosure to weaponized exploit collapses from weeks to hours. The defender's traditional patch/detect window disappears. Human-tempo detection engineering (author, review, deploy) cannot keep pace with automated exploit generation.

ARGUS counter: Exploit-to-Detection Synthesis — draft ES|QL/EQL rules directly from CVE + PoC within minutes of disclosure, gated by backtest + regression.
Pressure #2

Exploit-Variant Explosion

A single vulnerability spawns N polymorphic variants — different encodings, loaders, LOLBins, evasion paths. A detection rule tuned to the first public PoC is bypassed by the second. Rule quality must be measured against an evolving mutation set, not a static one.

ARGUS counter: Mutation-robust detection evaluation — rules are scored against generated exploit variants (detection.mutation_robust evaluator) before they ship.
Pressure #3

Agentic Adversary Behavior

Attackers become long-running goal-directed agents: reconnaissance, exploitation, lateral movement and exfiltration are orchestrated by a planner that reasons about the defender's responses. Telemetry shape changes — fewer obvious signatures, more goal-aligned sequences.

ARGUS counter: Defender autonomy matched to attacker autonomy — long-running planner agents (meta, deteng, hunter, triage) operating on .soc-* state with governance-gated mutation.
Pressure #4

Capability Asymmetry

The attacker has a frontier-class reasoner. The defender typically does not. Without deliberate design choices, the SOC becomes a slow, signature-bound fixed function against a fast, reasoning adversary — a losing geometry.

ARGUS counter: Telemetry moat + stack-native reasoning agents. Elastic's data gravity is the asymmetric advantage the attacker cannot replicate remotely.
2 Design Principles
Five non-negotiable principles. Every feature we ship must answer to at least one of them; features that violate them get cut.
Principle 1

Defender autonomy matches attacker autonomy

If the adversary is a long-running goal-directed agent, the defender must be too. ARGUS operates as a mesh of planner-class agents with shared state in Elasticsearch — not a human running queries with copilots. Autonomy is not a feature; it is the architectural baseline.

Principle 2

Telemetry is the moat

The frontier model's ceiling is set by the data it reaches. ARGUS treats the Elastic telemetry surface — endpoint, network, cloud, identity, and agent reasoning traces — as a single queryable substrate. The attacker's reasoner does not have this; we exploit that asymmetry.

Principle 3

Autonomous action is auditable and gated

Every mutation — rule patch, rule creation, exception, containment — passes through a snapshot → backtest → regression → apply → observe → rollback cascade. Every decision writes a reasoning trace to .soc-autonomy-decisions. No black-box autonomy.

Principle 4

Detection quality is continuously measured

Rules ship with numbers: precision, recall, mutation-robustness, FPR-on-benign, p95 latency. The detection eval harness replays Caldera-sourced scenarios and mutation sets through the rule preview API on every proposed change. A rule without a score does not ship.

Principle 5

Elastic-Stack-native in production

Caldera earns its keep as a telemetry generator. Everything production — detection, correlation, reasoning, governance, evaluation, UI — is built on Elasticsearch, Kibana, Workflows, Agent Builder, @kbn/evals, Task Manager, and native OTLP. No Python sidecars in the critical path.

Non-goal

We are not trying to out-reason the attacker

ARGUS wins through data proximity, speed of mutation, and governance rigor, not by fielding a bigger reasoner. The strategy assumes we will always be 6–18 months behind frontier capability — and designs for resilience under that assumption.

3 The Five-Layer Architecture
ARGUS organizes capabilities into five layers, each with a distinct contract. Existing Elastic work maps cleanly into these layers; the Δ Mythos-era deltas are the new investments Phase 2 delivers.
1 · Sensing
Ground truth at machine speed. Endpoint, network, cloud, identity, AI-tool usage (Shadow AI Discovery Pack), reasoning-trace spans. Single schema, ECS-aligned, queried by everything upstream.
Elastic Agent · Fleet · Endpoint · osquery
integrations#18123 · logs-argus_eval.* · OTLP
Δ reasoning-trace ingest
2 · Hypothesis
Reasoning over the telemetry. Triage, proactive hunt, detection engineering, correlation, attack-chain reconstruction. Planner-class agents that emit proposed mutations, not autonomous actions.
soc-alert-sweeper · soc-deteng · soc-proactive-hunter
kibana#257949 (XDR correlation) · kibana#259559 (default skills)
Δ exploit→detection synth · zero-day hypothesizer
3 · Validation
Quality gate before any change touches production. Backtest against historical alerts, regression dataset replay, mutation-robustness scoring, FPR-on-benign measurement. The heart of the "detection eval vertical."
soc-rule-backtester · soc-regression-gate · @kbn/evals
security-team#16546 (AESOP + online evals)
Δ M2.1 · detection eval vertical
4 · Action
Gated autonomous execution. Rule deploy, exception, host isolation, account disable, IOC blocklist. Snapshot → apply → post-apply observe → rollback on regression. Nothing irreversible without explicit operator approval.
soc-autonomous-applier · soc-post-apply-observer
soc-recovery · soc-response · soc-containment-playbook
Δ trust-tier thresholds for frontier-class mutations
5 · Governance
Every autonomous decision is auditable. Trust scoring per agent, budget + cooldown + kill-switch enforcement, full reasoning traces, shift handover narratives, evolution log, dead-letter routing.
soc-trust-scorer · soc-watchdog · soc-self-learning-loop
.soc-autonomy-decisions · .soc-evolution-log · .soc-audit-trail
Δ M2.5 · reasoning-trace governance (OTLP→ES)
Layer Contract

Layers communicate through Elasticsearch state, not RPC. Each layer writes structured documents with a stable schema; downstream layers read. This is a deliberate design choice: it makes the system trivially auditable, replay-testable, and survivable across agent restarts. It is also how we keep the frontier reasoner honest — everything it "decides" is a document we can inspect.

5 24-Week Roadmap
Three phases. Phase 1 establishes narrative and demo posture. Phase 2 delivers the five Mythos-specific capabilities. Phase 3 closes the autonomy loop and productizes the console.
Phase 1 Foundations & Narrative Weeks 0 – 4
  • ARGUS threat model this doc — primary strategic artifact; named adversary pressures, design principles, layer map.
  • ARGUS architecture one-pager — printable, demo-ready diagram of the five layers + two-paragraph pitch.
  • Capability mapping matrix — every existing Kibana PR / security-team issue mapped to a layer and pressure.
  • Mythos-era simulation preset — mythos_class_adversary Caldera profile (telemetry-only, sandboxed).
  • Demo storyboard v1 — three scripted scenarios (CVE response, frontier simulation, governance trace), ~10 min total.
Exit criterion: a single person can walk the demo end-to-end using these artifacts with zero slide deck.
Phase 2 Mythos-Specific Capabilities Weeks 4 – 16
  • M2.1 · Detection Eval Vertical — new sub-issue under security-team#16546. Evaluators: detection.precision, .recall, .mutation_robust, .fpr_on_benign, .latency_p95. Data stream logs-argus_eval.scenarios-*. Workflow soc-detection-eval.yaml wired to the rule preview API.
  • M2.2 · Exploit-to-Detection Synthesis — extends kibana#258362 (deteng skill) with a synthesize_detection_from_exploit tool: CVE + PoC → draft rule → auto-backtest → pending_review.
  • M2.3 · Mythos-era Exploit Probability — extends kibana#258041 (vuln checker) with a mythos_era.exploit_probability_24h field enriched from KEV / EPSS / SSVC / public PoC availability.
  • M2.4 · Frontier-Adversary Simulation Mode — level-6 preset in the difficulty controller; goal-directed chained profile emulating planner-class adversary behavior. Caldera-only, sandboxed.
  • M2.5 · Reasoning-Trace Governance — every ARGUS agent emits OTLP spans into Elasticsearch; every .soc-autonomy-decisions row carries trace_id. Auditable chain-of-thought.
Exit criterion: end-to-end demo — new CVE published at T+0 ⇒ rule drafted, evaluated, gated, applied, trace visible — in under 15 min.
Phase 3 Closing the Loop Weeks 16 – 24
  • Drift detection — eval scores decaying over time trigger mutation proposals (retrain / redesign / deprecate) via the meta-agent.
  • Trust-tier thresholds for frontier-class mutations — higher bar for rules that originated from exploit synthesis; more human-in-the-loop until trust is earned.
  • Playbook learning loop — containment outcomes feed back into soc-containment-playbook skill; successful chains are reinforced, failures deprecated.
  • Glasswing-compatible ingestion — optional feed of defender-facing intelligence (if/when Anthropic opens it) flows into the Sensing layer as an enrichment source.
  • ARGUS Console — dedicated UI in the Security Solution plugin: mutation cascade timeline, reasoning-trace viewer, scorecard, demo mode.
Exit criterion: system self-maintains under a realistic adversary mix for 30 consecutive days with operator approval rate > 80% and rollback rate < 2%.
